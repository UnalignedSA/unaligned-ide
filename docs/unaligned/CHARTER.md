# Unaligned IDE: project charter

Read this first: what the product is, its design language, the state of the fork and its rules.

## What this is

A fork of the Zed editor (Rust, GPUI) being turned into a new, free, open-source IDE made for coding with AI. Unaligned (https://unaligned.pw) is a privacy-first, pay-as-you-go AI API paid in crypto, OpenAI- and Anthropic-compatible (API at https://api.unaligned.pw). The IDE is a product for its users and for everyone.

Working name: **Unaligned IDE** (identifier `unaligned-ide`). It is a working name. Every occurrence comes from one central place, `crates/branding/brand.env` (read by the `branding` crate and by packaging scripts), so it can be changed in one edit: use `branding::PRODUCT_NAME` and its siblings, never a literal.

## The brief

> An IDE for Windows/Linux (so the current fork) that is free, open-source, fast, optimised, made for AI (simplified connection: API key or subscription or both, the user chooses what to use). Basically I want the best IDE that is easy to use for AI. Modern, beautiful, several built-in themes, being able to move the elements around (folders / AI chat / terminal, etc.) by drag and drop. Of course it promotes Unaligned well as a provider. I really want something redone, not 2-3 modifications.

Earlier requests in the same project, still valid:
- "A new graphical interface, modern UI/UX, Visual Studio Code style": VS Code's layout and habits (activity bar, side bar, editor tabs, bottom panel, status bar, command center, keymap).
- "The AI must work like Cursor, simple to use": one obvious chat, Agent/Ask, inline edit on Cmd/Ctrl+K, chat on Cmd/Ctrl+L, accept/reject of edits.
- "I want to integrate several providers, the user can connect any LLM": Unaligned is featured and recommended, never exclusive.
- The Unaligned website's look is the brand reference (see Design language).

## Product principles

1. Easy first. A person who has never configured an AI tool must be chatting with a model within a minute of first launch. Advanced options exist but stay out of the way.
2. Made for AI, still a real editor. Nothing an editor user relies on (LSP, git, terminal, debugger, search, extensions for languages) may be broken or hidden.
3. The user chooses how to pay for AI: API keys (Unaligned first, then any provider or custom endpoint), subscriptions they already have (ChatGPT, Claude through Claude Code, GitHub Copilot, SuperGrok, Gemini CLI: whatever the code base can support without a Zed account), local models, or several at once.
4. Privacy first, like Unaligned: no telemetry by default, no account required, nothing sent to Zed's servers without an explicit, visible reason.
5. Fast. Zed's performance is the product's base: never add work to hot paths (rendering, typing, scrolling, startup), never add heavy dependencies for decoration.
6. Windows and Linux are the release targets. macOS is where it is developed (this machine). Code under `cfg(target_os = "windows" | "linux")` matters more than the macOS path, even though it cannot be run here.
7. Open source and honest: GPL-3 obligations respected, Zed's trademarks and hosted services removed from the product, upstream credited.

## Design language

Reference: the look of the Unaligned website (https://unaligned.pw).

- Default theme "Unaligned": dark, warm near-black, flat. No gradients, no decorative shadows, no glow, no glass. Structure comes from 1px lines and three background levels.
- One accent, Swiss red, reserved for the primary action, the active/selected marker (2px bar or underline), the cursor and the selection. Destructive actions are outlined red, not filled.
- Square corners in the Unaligned family. Corners are a theme property since wave 1: `"corners": "square" | "soft" | "round"` in a theme's `style` (unset means round, so One, Ayu and Gruvbox look as upstream), and a user setting `corners` that overrides it. `rounded_xs … rounded_3xl` follow it; `rounded_full` always rounds; a badge or pill that must be square in a square theme uses `StyledExt::rounded_pill()`.
- Typography: UI font Onest, code font JetBrains Mono, display font Unbounded for very large headings only (`ui::DISPLAY_FONT`). All bundled in `assets/fonts`. Small labels and section headers: mono, uppercase, extra small, faint (`ui::SectionLabel`).
- Buttons: primary = filled accent with the theme's `accent.foreground` (`Button::primary`, `IconButton::primary`; one per region); secondary = outlined; ghost for toolbars. Inputs: sunken background, 1px line, border to text colour on focus (`ui::InputShell`).
- Density follows VS Code: activity bar 44px, title bar ~36px, tabs ~35px, status bar ~23px, list rows 22-24px, panel headers ~35px.
- Always use theme tokens (`cx.theme().colors()`, `cx.theme().status()`, `Color::…`), never hex values in Rust. The Unaligned palette lives in `assets/themes/unaligned/unaligned.json`.

## State of the fork (2026-11-13, version 0.1.0)

What a user sees and what the code offers now:
- **Identity and isolation**: the `branding` crate (`crates/branding/brand.env`); the app's own directories, log file (`unaligned-ide.log`), keychain prefix, single-instance port, mutex and pipe names. Menus, the About window (with the credit "Based on Zed"), the licences page, the command palette (Title Case names, "App:" instead of "zed:"), the app icon, the first-launch page, the welcome page and Settings say Unaligned IDE, and so do the connection and sign-in path, Settings → AI and the agent's system prompt since wave 5. `script/unaligned/check-branding` guards the text a user can read or reach (every accepted hit has a reason in `branding-allowlist.txt`; those marked OPEN are identities registered with third parties under upstream's name: what is sent to GitHub Copilot, the ChatGPT `originator`, the provider name sent with feedback on Mercury predictions). Since 2026-11-13 it also reports the kind `word` (`zed` in lower case as a word or as a part of a name, and "Zed" glued into a name) and scans `assets/keymaps/**` with its subfolders; its header has the exact definition. The version is 0.1.0 (`branding::UPSTREAM_VERSION` keeps 1.30.0 for the credit). The command-line tool is never installed under one of upstream's names, never registers upstream's link schemes and refuses `--uninstall` (W4-10).
- **Names, since 2026-11-13** (`script/unaligned/rename-upstream-names`, re-runnable; its header is the reference): the application is the cargo package `ide` in `crates/ide`, its binary is `unaligned-ide`, its main module is `app`; the crates `app_actions`, `app_env_vars`, `app_credentials_provider`; the action namespace `app::` (the palette's "App:"), with `RegisterUrlScheme`, `OpenAppUrl`, `ContactSupport`, `OpenSourceRepository` and `edit_prediction_onboarding::OpenEditPredictionOnboarding`; every environment variable and constant is `IDE_…` (task variables too: `$IDE_FILE`, …; a task template written with the old `ZED_` prefix is still accepted, because extensions from the registry use it: `current_variable_name` in `crates/task/src/task.rs`); a project's own folder is `.unaligned/` (`branding::PROJECT_DIR`; a `.zed/` folder is no longer read); the internal link schemes are `ide://`, `ide-cli://`, `ide-dock-action://` (the scheme registered with the system stays `branding::URL_SCHEME`); icon and picture files are `app_*`; in the terminal `TERM_PROGRAM` is `branding::APP_ID` and `IDE_TERM` is set; the command's flag `--zed <path>` is `--app <path>`; the base keymap that was called "Zed" is written and listed as "Native" (the value "Zed" of an older settings file is still read). Left alone on purpose: licence texts, `NOTICE` and copyright lines; the extension API (`zed_extension_api`, `zed::` inside extensions, `zed:extension`); Rust identifiers, module and file names inside the crates (`ZedPredict`, `zed_urls`, `get_zed_cli_path`, …); the git dependencies on upstream's forks in `Cargo.toml`. Side effects: credentials, saved chat mentions and sockets of development builds made before the rename are not found by a build made after it; external ACP agents now receive `ide://` mention links (an adapter that treats `zed://` links specially would show the bare address: not checked).
- **Nothing reaches Zed's services, and nothing is asked at start-up any more**: no sign-in, no account, no telemetry sender, no crash upload, no feedback upload, no hosted model provider, no collaboration. Updates are announced from the product's own GitHub releases (not configured yet), never installed. Zed's extension registry is contacted only when the Extensions page opens, when a file needs a listed language extension, and at most once a day while an extension is installed; the page says so. The public agent registry (`cdn.agentclientprotocol.com`) is no longer contacted at start (W4-09): only when an agent is set up or started, or once per session when the settings name a registry agent the copy on disk does not know. An external agent, once started, contacts its own vendor before any prompt (measured for Claude Code). On Windows the agent's sandboxed terminal is unavailable: its helper was a download from Zed's servers and is refused (W5-05). Since 2026-11-13: upstream's usage reporting to Anthropic (a POST to `/v1/log/zed` signed with the user's own key) reports nothing (`crates/language_models/src/provider/anthropic/telemetry.rs`); ACP client names, the tsserver host info and the author of the agent's hidden checkpoint commits (`PRODUCT_NAME <APP_ID@localhost>`) carry the product's identity; the app presents no client metadata document to MCP OAuth servers and registers itself with each server instead (`branding::OAUTH_CLIENT_METADATA_URL` is empty; a server that only accepts a metadata document needs a pre-registered client id until the owner publishes one). Still upstream's: the extension registry `api.zed.dev`, three helper packages fetched from upstream's GitHub organisation, and the three third-party identities marked OPEN above.
- **Links**: the site has API documentation only and no manual of the IDE, so Help → Documentation and vim's `:help` open the documentation home (`branding::DOCS_URL`), and the links to pages that do not exist there were removed from the interface (sandboxing, skills, tasks, remote development, REPL, the "docs" buttons of the debugger and of keybinding conflicts, several "Learn more"). The feedback actions open `branding::SUPPORT_URL` (`https://unaligned.pw/contact`) until `ISSUES_URL` is set. `server_url` and the `"zed.dev"` provider block are gone from `assets/settings/default.json`; old user files that have them still parse.
- **Frame, rebuilt in wave 3 from the shared parts**: title bar with one branch chip and a command center centred on every platform (window-control insets computed for macOS, Windows and Linux); status bar of 11px micro-labels with the AI chip at its right end (`CONNECT AI`, or the Unaligned balance and the model); one activity bar for every panel; the bottom panel has one header row that carries the terminal's or the debugger's buttons; docks resize within limits and a side dock snaps closed; Explorer, Outline and Source Control share one header, one row height, one selection rule; pickers are one raised surface at one width with a shared query row and footer; the theme selector lists the family first. Any panel, the chat included, can be dragged to any dock; Layout menu with Classic, AI-First, Zen and Reset.
- **Themes**: five of the product's own, checked by `script/unaligned/check-themes` (Unaligned, Unaligned Light, Unaligned Dusk, Unaligned Midnight with an azure accent, Unaligned Contrast), plus One, Ayu and Gruvbox. Corners are a theme property with a `corners` setting; `accent` setting. The two-square brand mark keeps the logo's colours in every theme (fixed red `#e5322d` in front, the text colour behind).
- **Design system** in `crates/ui`: `ui::metrics`, `Button::primary`, `ui::scrim`, `SectionLabel`, `PanelHeader`, `TextTabStrip`, `InputShell`, `selected_marker`, `EmptyState`, a neutral `CountBadge`; used by every surface rebuilt in waves 2 and 3. Since wave 5 switches are square in the family (`rounded_pill`), disabled `Button` and `IconButton` labels use `Color::Disabled` without extra dimming, `text.faint` falls back to `text.muted`, and `ui::metrics::title_bar_height(window)` exists.
- **First launch**: a "Get Started" page with three choices (theme on the five family tiles, picked with a click: the whole-window preview on hover was removed on 2026-11-13, it could stay on screen until the next settings reload; AI; keys) and one "Start Coding"; then the welcome page with the chat beside it. Settings has an Appearance page (theme tiles, mode, corners, accent, density, fonts) and no Collaboration or telemetry rows.

Claude Code, Codex and Gemini CLI are set up from their row (download from the public agent registry, their own sign-in); ChatGPT, SuperGrok and Copilot sign in through the providers' embedded views. ## How to build, run and look at it (macOS dev machine, no Xcode)

- Toolchain is pinned by `rust-toolchain.toml`. This Mac has only the Command Line Tools, so the Metal shader compiler is missing: always pass `--features gpui_platform/runtime_shaders` when building or checking the `ide` crate.
- Check one crate: `cargo check -p <crate>`. Whole app: `cargo check -p ide --features gpui_platform/runtime_shaders`.
- Build and run: `cargo build -p ide --features gpui_platform/runtime_shaders`, then `./target/debug/unaligned-ide --user-data-dir <dir> <folder>`. ALWAYS pass `--user-data-dir` (for example a fresh directory under `.work/`). Since wave 1 it isolates everything: data in `<dir>`, config in `<dir>/config`, state, cache and logs (`<dir>/logs/unaligned-ide.log`) beside them. Without it the app no longer touches Zed's files, but it writes the product's own directories in the owner's home (`~/.config/unaligned-ide`, `~/Library/Application Support/unaligned-ide`, …), which agents must not do.
- Debug builds read `assets/` (themes, settings, keymaps, fonts, icons) from disk at run time: asset-only changes need no rebuild, only a restart.
- Tests: `cargo test -p <crate> <filter>`. For crates that pull `gpui_apple` in the test profile (`ide`, `agent_ui`, `gpui`, `livekit_client`) the form that compiles here is `cargo test -p <crate> -p gpui_platform --features gpui_platform/runtime_shaders`. Never claim tests pass without the command and its result line.
- Linux and Windows: `script/unaligned/check-linux [-p <crate>]` and `script/unaligned/check-windows [-p <crate>]` type-check in Docker (`docs/unaligned/PLATFORM-CHECKS.md`); they are run at every gate. Nothing is linked or run on those systems by these checks.
- Screenshots: `script/unaligned/shot <scene or name>`, see `docs/unaligned/SCREENSHOTS.md` (since wave 2: `press` / `drag_to` / `release` steps to picture a drag, and `--no-capture` to run steps without a picture). With the screen unlocked it captures the instance's own window (only ever that window, never the full screen); with the screen locked it uses the offscreen backend, which needs `script/unaligned/build-offscreen` after each build of the app.
- Network: `script/unaligned/netcheck` lists the hosts an instance contacts (`docs/unaligned/NETWORK.md`).
- The command-line tool (`cargo build -p cli`) of a development build: on macOS it has no `.app` around it, so name the editor with `--app target/debug/unaligned-ide`; on Linux and Windows it finds `./unaligned-ide` beside itself.
- Merging upstream: check upstream's commit out on a temporary branch, run `script/unaligned/rename-upstream-names` there, commit, and merge that branch; then `cargo check` regenerates `Cargo.lock`. The script's header has the details. Files deleted here that upstream changed come back as conflicts: keep them deleted.
- Verified after the 2026-11-13 rename, on the development Mac: `cargo check --workspace --all-targets` (with the shader feature this Mac needs) passes; `script/unaligned/check-linux` and `check-windows` pass for `-p ide`, and for `-p cli` (Linux also `-p remote_server`); a development build starts, six scenes were captured with `shot` (command palette, chat with the stand-in API, settings, terminal, keymap editor, full layout) and the log of the run has no key-binding or start-up error; `netcheck --scenario all --expect target` passes; `check-branding`, `check-themes`, `script/check-keymaps` and `script/check-todos` pass. Tests: `cargo test` over 65 packages of the workspace ran 7,863 tests; the nine that failed because of the rename (test data the script had not followed) were fixed and pass. Failing or hanging before the rename too, checked on the commit before it: `editor_tests::test_backspace_after_deletion_hunk`, `editor_tests::test_completions_default_resolve_data_handling`, `extension_suggestions::tests::test_suggestion_returns_after_failed_install`, two tests of `edit_prediction` (`test_edit_prediction_v4_end_of_buffer`, `test_free_plan_edit_predictions_ended_for_zed_provider`), and thirteen tests of `edit_prediction` that never return (the two that were tried on the older commit hang there too). Not re-verified after the rename: `bundle-linux` and `bundle-windows.ps1` (never run with the new names), the two GitHub workflows, the whole `shot-all` set and the offscreen build.

## Rules

1. Do not bring upstream's name back. New files, crates, actions, variables, settings keys, sockets and anything sent to another program take the product's names (`branding::…` in code, `IDE_…` for variables, `app::` for actions, `.unaligned/` for a project's folder). `script/unaligned/check-branding` must end with PASS; a new allowlist entry needs a reason and stays as narrow as that reason. The credit to Zed (README, licence texts, `NOTICE`, About) is not a trace to remove.
2. The product's name, identifiers and URLs come from `crates/branding/brand.env`: never a literal.
3. Do not rename public types, actions, settings keys or panel names without a reason; keep key bindings, focus handling and accessibility attributes working.
4. Follow the Rust and GPUI guidelines in `.rules` (`AGENTS.md` and `CLAUDE.md` are links to it).
5. No secrets in the repository. API keys never go in files, logs or screenshots.
6. The tooling starts its own instances with their own data directory (`--user-data-dir`), under `.work/`: never run it against the data of an installed copy.
7. The workflows in `.github/workflows/` are hand-written. Upstream's generator (`cargo xtask workflows`) was deleted: do not bring it back.
8. Say what was verified and how, and what was not.

Identifiers such as `W2-01` in comments, in the allowlist and in these pages name the tasks of the first build of the fork. Their briefs and reports are working notes that are not in the repository.
